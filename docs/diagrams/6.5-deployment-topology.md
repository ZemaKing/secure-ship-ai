# 6.5 Deployment / local dev topology

> Regenerated against the actual `docker-compose.yml` (Week 5, post-stretch-goal). Corrected from the `REQUIREMENTS.md` Mac-oriented starting reference: this build runs on Windows (Docker Desktop, WSL2 backend) — the "full Metal acceleration" framing doesn't apply either way, since this machine has no dedicated GPU (Ollama is CPU-only whether host-native or containerized — that's *why* containerizing it was a low-risk Week 5 stretch goal here rather than the genuine performance trade-off the Mac doc describes). Frontend serves on **`:5173`** (Vite dev server), not `:3000`. Twilio was never built — it stayed a documented "optional stretch" that was never picked up; shown here only as explicitly not implemented, not as a live integration point.

> No performance trade-off either way on this machine (CPU-only, no GPU to lose by containerizing) — so moving Ollama into Compose was a pure Docker-wiring exercise. Twilio (real SMS) was never built anywhere in this repo; the mock-SMS path (`tools/send_verification_code.py`, console `print()` only) is the only implementation that exists, and is not shown in this diagram as a live external dependency.
